10 вариантов взаимодействия микросервисов через брокер сообщений (Kafka):

Student → Payment: событие регистрации студента для выставления стартового платежа.

Payment → Student: событие подтверждения платежа для разблокировки доступа к курсам.

Library → Student: событие о просрочке возврата книги для ограничения записи на курсы.

Student → Library: событие отчисления студента для авто-закрытия активных займов.

Teacher → Gradebook: событие создания задания для массового создания записей оценивания.

Gradebook → Student: событие публикации оценок для обновления сводных данных студента.

Attendance → Gradebook: событие пропуска занятия для штрафа в оценке посещаемости.

School → Teacher: событие изменения расписания для обновления слотов преподавателя.

Payment → Teacher: событие выплаты преподавателю для актуализации баланса и отчётов.

Library → School: событие добавления нового учебника для обновления каталога курсов.
